# Art direction brief — Project Z

Версия 1.0, 2026-11-06. Формат: шаблон скилла `create-game-assets`. Пометка **[предложение]** — решение принято мной по умолчанию, пользователь не подтверждал.

## 1. Рамка игры

- Фантазия игрока: выжить и пробиться через толпы в мрачном, тесном мире, оставляя за собой кровавый след.
- Основные глаголы: бить, уклоняться, добивать (финишер), расчленять.
- Движок и рендер: Godot 4.7.2, 3D-сцена, **Sprite3D**, камера Camera3D.
- Платформа: Windows (ПК).
- Камера: фиксированная, ортографическая, наклон 30° сверху (по референсу героя).
- Нативный вьюпорт: **960×540**, показ **×2** до 1920×1080 (целый коэффициент, Nearest). Решение 2026-11-06, причина: толпы врагов (см. ниже).
- Размер героя на экране: холст 64×96, рост ≈88 px. Враги: рядовые 48×80…64×96, крупные (мехи) 128×128 и больше.

### Почему 960×540

| Вьюпорт | Масштаб | Герой от высоты кадра | Видимая арена | Вывод |
|---|---|---|---|---|
| 480×270 | ×4 | 33% | ≈ 8.6 × 9.6 м | толпе негде стоять |
| 640×360 | ×3 | 24% | ≈ 11.4 × 12.9 м | тесно для толп |
| **960×540** | **×2** | **16%** | **≈ 17 × 19 м** | помещаются 30–50 врагов, герой читается |
| 1920×1080 | ×1 | 8% | ≈ 34 × 39 м | герой слишком мелкий, пиксель теряется |

Промежуточные варианты (1280×720) дают нецелый масштаб до 1080p, пиксели «гуляют». Для 1440p (×2.67) — показ ×2 с полями или ×3 с обрезкой, решим позже.

### Камера и пиксельная сетка (для движка)

| Параметр | Значение |
|---|---|
| Проекция | Orthogonal |
| Масштаб | 1 м мира = 56 px (герой 100 ед. модели ≈ 1.79 м). `Camera3D.size` (по вертикали) = 540 / 56 ≈ 9.643 |
| Sprite3D | `pixel_size = 1/56 ≈ 0.017857`, `billboard = enabled` (полный), фильтр Nearest, `alpha_cut = discard`, `offset = (0, 48)` для холста 64×96 (низ холста на точке опоры). Проверено в движке: кадр совпадает с исходником 2200/2200 px |
| Наклон камеры (pitch) | **−30°**; спрайты персонажей рендерятся под этим же углом |
| Поворот (yaw) | 45° |
| Привязка | позиция камеры кратна 1/56 м, иначе пиксели «плывут» |

Спрайт уже нарисован под углом камеры, поэтому в движке используется **полный billboard**: без сжатия и без растягивания арта. Pivot спрайта (стопы) ставится на точку персонажа на полу, спрайт приподнимается так, чтобы пол не резал ноги.

Пол: квадратная текстура на 3D-плоскости, плотность 56 px на 1 м (тайл 1×1 м = 56×56 px, или 2×2 м = 112×112). На экране 1 м пола = 56 px в ширину и 28 px в глубину (sin 30° = 0.5).
## 2. Визуальная система

- **Язык форм:** угловатые, рваные силуэты, острые выступы (оружие, лохмотья, кости). Героя можно узнать по силуэту. Жертвы и враги отличаются формой, не цветом.
- **Приоритет силуэта:** голова, оружие и поза читаются на 1× без увеличения. Мелкие детали не должны ломать силуэт.
- **Структура значений:** фон тёмный и холодный, герой и враги светлее фона, кровь — самое насыщенное пятно в кадре.
- **Палитра:** PZ-28, файлы в `art\palette\`. Никаких цветов вне палитры. С 2026-11-10 в ней 30 цветов: в конец добавлены brass-dark `#3e2c1c` и brass-mid `#74582a` (провал в латуни, мех-разведчик); имя файлов и индексы старых цветов прежние.
- **Материалы:** кожа и мясо тёплые (flesh), металл холодный (steel), камень и ткань серо-фиолетовые (shadow), лампы и огонь (lamp), болезненное свечение (sick-green).
- **Контур:** селективный (sel-out): внешний контур цветом самого тёмного соседнего тона в оттенке материала, не чистый чёрный. Внутри контуров нет. Толщина 1 px.
- **Свет:** главный источник сверху-слева-спереди. Тени падают вправо-вниз. Объекты светлее со стороны источника, у основания темнее.
- **Контраст:** низкий общий, высокий только на героях, оружии и крови.
- **Плотность деталей:** низкая-средняя. Один главный акцент на объект.
- **Движение:** короткая анимация с сильными позами. 4-6 кадров на цикл ходьбы, 3-5 на удар (ключевые позы, широкая «замашка», кадр удара держим дольше).
- **Исключения:** сглаживание (anti-aliasing), градиенты, полупрозрачность (кроме тени), размытие, цвета вне палитры, чёрный контур 1 px вокруг всего, текст внутри спрайтов.

### Правила крови и gore

- Кровь строится рампой blood-1…blood-wet. Свежая кровь: blood-wet блик на blood-4/5, застывшая: blood-2/3, без блика.
- Пятна на полу: форма из 2–3 слоёв (тёмный край, средний, светлый блик), плоские.
- Ошмётки и конечности — отдельные спрайты и частицы, не часть спрайта врага.
- Размер брызг подчинён читаемости: в кадре крови много, но герой и враги остаются читаемыми.
- Dither допустим только для земли и текстур пола, не для персонажей.

## 3. Технический контракт

| Параметр | Значение |
|---|---|
| Формат | PNG, RGBA, 8 бит, без сжатия с потерями |
| Фон | прозрачный (альфа 0 или 255, без полупрозрачных пикселей) |
| Холст героя | **64×96** (герой ≈88 px ростом, детализация как на референсе), враги по таблице манифеста |
| Сетка | пиксель = 1 px, масштаб только целый |
| Pivot | bottom-center (стопы), центр по X, нижняя линия стоп на последней строке холста минус 2 px под тень |
| Кадры | один лист на анимацию: **строки — направления** (s, se, e, ne, n, nw, w, sw), столбцы — кадры; теги `<анимация>_<направление>` и длительности кадров в Aseprite |
| Анимации героя | idle 1 кадр; walk 8 кадров, 10 fps, 1.19 м/с; run (раунд 7) — запись Running Fast, 8 кадров по 63 мс, 5.2 м/с. Высота таза считается из положения стоп (`pelvis_drop`): опорная нога никогда не перетягивается, стопы не отрываются от пола. Скорость в игре = скорость из `hero_render.py` (`gait_speed`), иначе стопы скользят |
| Боевые анимации героя | `tools/attacks.py`. Удары — ключевые кадры Mixamo (`refs/mixamo/*.dae`) с длительностями под вес оружия: тяжёлое — долгий замах с удержанием, короткий удар, хит-стоп 130–150 мс; лёгкое — без удержаний. Стрельба собрана на скелете героя. Рядом с листом `<имя>.json`: `durations_ms`, `hit` (кадры попадания), `chain` (начала отрезков серии), `root_m` (смещение корпуса, м: x — вправо героя, y — вперёд). Спрайт нарисован на месте, движок двигает героя по `root_m` |
| Эффекты | `tools/fx_gen.py` → `art/fx/`: вспышки (8 углов), гильза, пар (дизер), куски мяса, пятна крови fresh/dried (каждая строка экрана — две строки текстуры, декаль повёрнута по камере на 45°). Точки дула, выброса, вытяжки и острия — `anchors` в `layers.json` |
| Противник-человек | `tools/enemy_render.py` → `art/enemy/`: `E_` живой 64x96, `C_<исход>` труп 128x128 (центр — точка на полу; исходы intact, decap, arm_off_r, split, gut, blast), `P_<кусок>` 48x48 кувырок 8 кадров. Срезы — плоскости в координатах покоя, срез закрашен мясом с костью. Раунд 4: `E_air_*` живой в воздухе 128x128 (стопы y=125, таз на месте, подъём задаёт движок), `T_<исход>` тело, убитое в воздухе, кувырок 8 кадров 128x128, центр тела в центре. Раунд 6: трупы `C_<исход>_<падение>` 192x192, 11 исходов и 4 падения. Раунд 7: обгоревшие листы `<имя>_s` (`tools/enemy_scorch.py`, таблица цветов внутри PZ-28) |
| Оружие правой руки | все правые оружия (паровой клинок, серп, обрез) — модули парового протеза (`MODULE_PARTS` в `hero_render.py`, референсы `refs/hero_modules`); в левой руке всегда револьвер |
| Слои героя в игре | `tools/hero_layers.py`: `L_` ноги (по движению, к полу), `U_` корпус + правая рука с модулем (по прицелу, грудь в точке покоя), `A_` левая рука с револьвером под каждый кадр корпуса x4 состояния (готов, выстрел, отдача 1, 2), закрытое торсом вырезано. Порядок: L, U, A (A и U на 0,02 м ближе к камере). Смещение корпуса от таза — `offsets_px` кадра ног в `art/hero/layers/layers.json`. Цельные спрайты `hero_*.png` остаются для манекенов (64x96). С раунда 3 холст слоёв героя **128x128**, стопы на y=125, `offset = (0, 64)`, след удара на том же холсте. `R_` — левая рука в перезарядке (3 позы на кадр корпуса; корпуса idle, run, gun_aim, gun_aim_run). Сборка листов: `tools/hero_sheets.py` |
| Имена | `категория_имя_состояние_направление`, строчные, `_`, например `hero_idle_se.png` |
| Импорт Godot | Filter: Nearest, Mipmaps: off, Compress: Lossless, Repeat: off |
| Цвет | sRGB, без профиля |
| Лимит цветов | только PZ-28 (30 цветов); проверка `asset_report.py --max-colors 30` |
| Направления | 8, **все рисуются**: зеркалить нельзя, протез только на правой руке |

Папки: `C:\Project Z materials\art\<категория>\` (источники `.aseprite`, листы `.png`), готовое копируется в `C:\project Z\z\assets\`.

## 4. Визуальная цель (образцовый ассет)

- Первый ассет: **герой, idle, направление SE, 1 кадр, 32×48**. Он определяет стиль остальных.
- Герой: Владимир Чернов, учёный (см. `сюжет.md`). Оружие **утверждено**: механический протез руки, трансформируемый в оружие. Образ **[предложение]**: длинное пальто, гогглы, борода, паровой котёл-ранец; латунь (lamp) и сталь на протезе. Конкретный силуэт выбирается по эскизам `art\hero\silhouettes_v2.png`.
- Утверждение: после проверки на 1×, на 4× и на тёмном фоне уровня. Утверждает пользователь.
- Образцовый ассет и утверждённые варианты: `art\hero\`, манифест `docs\asset-manifest.json`.
- Не-примеры: ярко-цветной персонаж, чёрный контур вокруг всего, полупрозрачная кровь.

## 5. Процесс рисования

1. Персонажи: 3D-модель из SDF-примитивов (`tools/hero_render.py`) → ортографический рендер под pitch −30° в 8 направлений → квантование в PZ-28, sel-out, чистка шума → сборка в Aseprite (`tools/aseprite_build_hero.lua`: палитра, кадры, теги) → экспорт листа. Aseprite из PowerShell запускать через `Start-Process -Wait`, иначе команда не ждёт окончания.
2. После каждой итерации рендерим ×1 и ×8, смотрим на силуэт и на ошибки пикселей (одиночные пиксели-шум, «дублеры», изломы линий).
3. Проверяем скриптами из `create-game-assets` (`asset_report.py`, `build_preview_sheet.py`).
4. Утверждённое кладём в манифест со статусом, проверками и источником.
5. Только после утверждения образца делаем семейство (враги, оружие, окружение).
